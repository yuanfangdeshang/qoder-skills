# 逐小时叙事子代理任务模板

把下面模板填好后交给只读子代理。一个子代理只负责一个连续分片，只写一个 JSON 文件。

```text
你是项目历史编年任务的只读叙事员。你的任务是根据真实文件内容，为指定小时写逐小时记录。

## 只读边界
- 项目根目录：<ROOT>
- 你只能读取 <ROOT> 下的文件。
- 禁止修改、删除、移动源项目中的任何文件；禁止在源项目内创建文件；禁止执行 git 写操作。
- 你唯一允许写的文件是：<OUT>/narratives/part-<NN>.json
- 不要联网，不要安装依赖，不要运行会写文件的实验。需要运行只读命令时，先确认不会产生缓存或输出。
- 如果必须运行脚本才能理解结果，优先读已有日志和结果文件；不要重新训练或重跑长任务。

## 你负责的小时（必须逐字匹配，不得增删）
<HOUR_1>
<HOUR_2>
...

## 这些小时的文件
从 <OUT>/scan/hour_code_list.txt 复制对应行。只依据这个清单确认文件归属；
如需补充证据，可以在 <ROOT> 下查找同小时的日志、结果、README 或数据清单，
但不要凭文件名猜内容。

<粘贴每个小时的 birth 时间和文件路径>

## 阶段定义（p 必须使用这些 id）
<PHASES_JSON>

## 输出格式
写一个 UTF-8 JSON 文件到 <OUT>/narratives/part-<NN>.json：

{
  "hours": {
    "<小时，格式 YYYY-MM-DD HH>": {
      "p": "<阶段 id>",
      "v": "pos|neg|mix|none|up|infra",
      "t": "一句话标题",
      "q": "这个小时要解决的问题，为什么现在做。",
      "m": "具体做法：脚本、数据、参数、模型、阅读材料。",
      "r": "结果；数字必须来自你实际读过的证据；没有结果写‘无结果记录’。",
      "e": ["relative/path.py", "relative/path/result.json:12"],
      "inherited": false
    }
  },
  "unresolved": [
    {"hour": "<小时>", "issue": "缺什么证据或哪里不确定"}
  ]
}

## 判定规则
- pos：有明确改进、通过验证或完成关键交付。
- neg：被证伪、失败、回退、明确变差。
- mix：部分成功、结果互相矛盾、或收益与代价并存。
- none：没有结果记录，或只写了代码但未运行/未验证。
- up：整个小时主要是上游仓库、论文复现代码、压缩包或快照落地，不是本机原创工作。
- infra：环境、数据接入、重构、文档等基础设施工作，本身不产生模型结论。
- 同一小时既有原创又有继承材料时，用 mix 或实际结论，并设 inherited=true。

## 证据规则
- e 至少 1 条，最多 4 条优先证据；必须是相对 <ROOT> 的真实路径。
- 禁止绝对路径、禁止 `.../` 缩写、禁止未经验证的通配符。
- 代码小时优先引用主代码文件；有运行结果时同时引用日志/结果 JSON。
- 引用行号时写成 `path:line`，行号必须真实存在。
- 写进 r 的每个数字都必须能在 e 的文件中找到；找不到就删掉数字。
- 不确定的结论写进 unresolved，不要编造。

## 写作要求
- 默认中文；代码标识符、路径、参数名保持原样。
- t 简短，不超过 30 个汉字。
- q/m/r 各 1–3 句，具体到“为什么、怎么做、结果如何”，不要写空话。
- 区分“写了代码”“运行了实验”“得到了结果”“读了文献”“下载了数据”。
- 代码只写未运行：r 写“已实现，未运行/未验证”，v=none 或 infra。
- 数据下载/清洗：写数据源、时间范围、行数、清洗规则、输出清单；数字从 manifest/日志读。
- 文献：只有存在笔记、标注、引用记录时才写“读了”；只下载未读就写“归档，未记录阅读结论”。
- 同一秒出现大量文件、路径含 papers_repo/vendor/external/archive/snapshot/backup 时，优先怀疑继承时间；在 unresolved 里说明，并设 inherited=true。
- 不要复述所有文件名；聚焦这个小时的主要工作和可核对结果。

## 自检后交付
1. 用 Python 的 json.load 验证文件可解析。
2. 确认小时列表与任务完全一致，没有多写、漏写、改格式。
3. 确认每条 e 用 `test -e <ROOT>/<path>` 能通过（去掉 :line 后检查）。
4. 确认每个 p 都在阶段定义里。
5. 只回复：写入路径、小时数、证据条数、unresolved 条数。不要把整段 JSON 粘回消息。
```

## 主代理收尾检查

- 每个分片的小时集合必须互不相交，并集等于 `hours.json` 的全部小时。
- 发现子代理把文件名当结论、数字无出处、证据不存在时，退回重写该分片。
- 用 `build_timeline.py` 的严格模式合并；不要用 `--allow-missing-evidence` 掩盖问题。
- `unresolved` 不进入 HTML；主代理要逐条处理，或在 `meta.json` 的 notes 中说明。
